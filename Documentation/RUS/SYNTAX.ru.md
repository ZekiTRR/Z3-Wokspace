# Z3 Workbench — Справочник синтаксиса

Полная документация всех конструкций, операторов и команд, поддерживаемых
DSL и оболочкой Z3 Workbench.

Для обучающих материалов и разобранных задач см.
[Documentation.ru.md](Documentation.ru.md);
[ARCHITECTURE.ru.md](ARCHITECTURE.ru.md).

---

## 1. Инструкции

Завершители не нужны; порядок объявлений относительно ограничений не важен.

| Синтаксис | Пример |
|---|---|
| `var ИМЯ : ТИП ;`* | `var x: Int` |
| `constraint ВЫРАЖ` | `constraint x >= 10` |

\* реального `;` нет — инструкции разделяются неявно по ключевым словам.

Минимальная программа:

```dsl
var x: Int
constraint x > 0
```

---

## 2. Типы данных

| Синтаксис | Пример |
|---|---|
| `Bool` | `var flag: Bool` |
| `Int` | `var n: Int` |
| `Real` | `var ratio: Real` |
| `String` | `var name: String` |
| `BitVec(N)` | `var eax: BitVec(32)` |

Правила ширины для `BitVec(N)`:

| Правило | Пример |
|---|---|
| N должно быть 1..64 | `BitVec(32)` — ok · `BitVec(0)`, `BitVec(65)` — отклоняется |

Зарезервированные, пока не поддерживаемые типы: `Array`, float, enum.

---

## 3. Идентификаторы

| Правило | Пример |
|---|---|
| `[A-Za-z_][A-Za-z0-9_]*`, только ASCII, чувствительны к регистру | `x`, `_tmp`, `eax_01` |
| Уникальны внутри задачи | второй `var x` → ошибка |
| Ключевые слова именами быть не могут | `var`, `constraint`, `true`, `false`, `Bool`, `Int`, `Real`, `String`, `BitVec` |

---

## 4. Литералы

| Вид | Синтаксис | Примеры |
|---|---|---|
| Целый (dec) | `ЦИФРЫ` | `42`, `7` |
| Целый (hex) | `0xHEX` / `0XHEX` | `0x1337`, `0XFF` |
| Целый (bin) | `0bБИТЫ` / `0bБИТЫ` | `0b1010`, `0B11` |
| Вещественный | `Д.ДД` | `3.14`, `0.5` |
| Логический | ключевое слово | `true`, `false` |
| Строковый | `"ТЕКСТ"` | `"hello"` |

Отрицательные значения записываются минусом перед положительным
литералом: `-7`.

### Строковые escape-последовательности

| Escape | Значение | Пример |
|---|---|---|
| `\\` | обратная косая черта | `"a\\b"` |
| `\"` | двойная кавычка | `"say \"hi\""` |
| `\n` | перевод строки | `"line1\nline2"` |
| `\t` | табуляция | `"a\tb"` |

Любой другой escape — ошибка; строки не переносятся на новую строку.

---

## 5. Комментарии

| Синтаксис | Назначение | Пример |
|---|---|---|
| `// ТЕКСТ` | Строчный комментарий, до конца строки | `// init` |
| `/* ТЕКСТ */` | Блочный комментарий, может занимать несколько строк, без вложений | `/* bounds */` |

```dsl
/* настройка задачи */
var x: Int   // стартовое значение
```

---

## 6. Унарные операторы

| Оператор | Тип операнда | Результат | Бэкенд | Пример |
|---|---|---|---|---|
| `!E` | `Bool` | `Bool` | `not` | `!flag` |
| `-E` | `Int`, `Real` | тот же | `-` | `-x` |
| `~E` | `BitVec(N)` | `BitVec(N)` | `bvnot` | `~mask` |

Примечание: минус **не** применяется к `BitVec` в этом DSL.

## 7. Бинарные операторы (по приоритетам, от низкого к высокому)

Все бинарные операторы левоассоциативны. Операнды обязаны иметь одинаковые
типы (исключение — адаптация литералов из §9).

### Уровень 1 — логическое ИЛИ

| Оператор | Тип | Результат | Бэкенд | Пример |
|---|---|---|---|---|
| `A \|\| B` | `Bool` × `Bool` | `Bool` | `or` | `x < 0 \|\| x > 100` |

### Уровень 2 — логическое И

| Оператор | Тип | Результат |  Бэкенд | Пример |
|---|---|---|---|---|
| `A && B` | `Bool` × `Bool` | `Bool` | `and` | `x >= 10 && x <= 20` |

### Уровень 3 — равенство

| Оператор | Тип | Результат | Бэкенд | Пример |
|---|---|---|---|---|
| `A == B` | любой одинаковый тип¹ | `Bool` | `=` | `y == x * 2` |
| `A != B` | любой одинаковый тип¹ | `Bool` | `distinct` | `s != ""` |

¹ `Bool`, `Int`, `Real`, `String`, `BitVec(N)` с совпадающими ширинами.

### Уровень 4 — порядок

| Оператор | Тип | Результат | Бэкенд | Пример |
|---|---|---|---|---|
| `A < B` | `Int`/`Real`/равноширинный `BitVec` | `Bool` | `<` / `bvult` | `i < len` |
| `A <= B` | те же | `Bool` | `<=` / `bvule` | `n <= 9` |
| `A > B` | те же | `Bool` | `>` / `bvugt` | `c > 0x41` |
| `A >= B` | те же | `Bool` | `>=` / `bvuge` | `v >= 33` |

Сравнения BitVec — **беззнаковые**.

### Уровень 5 — побитовые И/ИЛИ/ИСКЛЮЧАЮЩЕЕ ИЛИ

| Оператор | Тип | Результат | Бэкенд | Пример |
|---|---|---|---|---|
| `A & B` | пара `BitVec(N)` | `BitVec(N)` | `bvand` | `v & 0xFF` |
| `A \| B` | пара `BitVec(N)` | `BitVec(N)` | `bvor` | `flags \| 0x80` |
| `A ^ B` | пара `BitVec(N)` | `BitVec(N)` | `bvxor` | `key ^ 0x1337` |

### Уровень 6 — сдвиги

| Оператор | Тип | Результат | Бэкенд | Пример |
|---|---|---|---|---|
| `A << B` | пара `BitVec(N)` | `BitVec(N)` | `bvshl` | `b << 2` |
| `A >> B` | пара `BitVec(N)` | `BitVec(N)` | `bvlshr` | `w >> 8` |

Арифметического (знакового) сдвига нет; сдвиги беззнаковые, как всё
остальное.

### Уровень 7 — аддитивные

| Оператор | Тип | Результат | Бэкенд | Пример |
|---|---|---|---|---|
| `A + B` | `Int`/`Real`/равноширинный `BitVec` | тот же | `+` | `x + y == 30` |
| `A - B` | те же | тот же | `-` | `p - q == 2` |

### Уровень 8 — мультипликативные

| Оператор | Тип | Результат | Бэкенд | Пример |
|---|---|---|---|---|
| `A * B` | `Int`/`Real`/равноширинный `BitVec` | тот же | `*` | `3 * key0` |
| `A / B` | `Real`×`Real`, пара `BitVec(N)` | тот же | `/` / `div` / `bvudiv` | `total / 4` |
| `A % B` | пара `BitVec(N)` | `BitVec(N)` | `bvurem` | `crc % 0xFFFF` |

### Уровень 9 — унарные (см. §6)

Самое сильное связывание: `!E`, `-E`, `~E`.

## 8. Сводка приоритетов

```text
1   ||
2   &&
3   ==  !=
4   <   <=  >   >=
5   &   |   ^          <- связывает сильнее сравнения (в отличие от C!)
6   <<  >>
7   +   -
8   *   /   %
9   !   -   ~          (унарные, самый сильный)
```

Примеры разбора неоднозначностей:

| Исходник | Разбирается как |
|---|---|
| `x ^ 0x1337 == 0x4242` | `(x ^ 0x1337) == 0x4242` |
| `1 + 2 * 3 == 7` | `(1 + (2 * 3)) == 7` |
| `x & 1 << 2` | `x & (1 << 2)` |
| `-x + y < 0` | `((-x) + y) < 0` |

---

## 9. Адаптация целых литералов к BitVec

Обычный целый литерал, стоящий операндом рядом с `BitVec`, автоматически расширяется до его ширины:

| Шаблон | Эффект | Пример |
|---|---|---|
| `bitvec_выраж ИЛИ ЦЕЛЫЙ_ЛИТЕРАЛ` | литерал становится `BitVec(W)` другого операнда | `(x ^ 0x1337) + 10 == 0x4242` (все литералы → BitVec(32)) |
| проверка диапазона | требуется `0 ≤ v < 2^W`; нарушения — ошибки | `x < 100` — ok · `x < -1`, `b8 < 300` — отклоняется |

Без соседа BitVec литерал остаётся `Int`. Вычисленные подвыражения никогда не адаптируются — только прямые литералы.

## 10. Правила типизации

| # | Правило | Текст ошибки (дословно) |
|---|---|---|
| 1 | Операнды бинарной операции имеют один тип | `Type mismatch: operator '…' requires …, got A and B` |
| 2 | Типы равенства: Bool/Int/Real/String/BitVec(одинаковая W); Array исключён | `Type mismatch: cannot compare A with B` |
| 3 | Ширины BitVec обязаны совпадать точно | входит в сообщения выше |
| 4 | `Int` и `Real` никогда не смешиваются неявно | `Type mismatch: operator '+' requires numeric operands of the same sort, got Int and Real` |
| 5 | Для строк доступны только `==` / `!=` | через семейство правила 1 |
| 6 | Корень каждого `constraint` обязан быть `Bool` | `Constraint must be a Boolean expression, got ТИП` |
| 7 | Переменная должна быть объявлена в задаче | `Unknown variable "name"` |
| 8 | Имена переменных уникальны в задаче | `Variable "x" is already defined` |

## 12. Поведение решателя

| Аспект | Поведение |
|---|---|
| Исходы | `SAT` / `UNSAT` / `UNKNOWN` (+ внутренний `Error`) |
| Таймаут | фиксированные 5000 мс на запуск в этой сборке |
| Модель | одно присваивание для ВСЕХ объявленных переменных (включено завершение) |
| Статистика | собирается из Z3 (conflicts, decisions, …) в результат |
| Потоки | решение выполняется вне GUI-потока; результаты приходят через очередь событий |
| Отмена | кооперативный флаг + ограничение таймаутом бэкенда |

## 13. Формат файла проекта (`.z3w`)

JSON, версия схемы 1; исходники — единственный источник истины:

```json
{
    "version": 1,
    "name": "Example",
    "problems": [
        {
            "name": "crackme_01",
            "source": "var x: BitVec(32)\n\nconstraint ((x ^ 0x1337) + 10) == 0x4242\n"
        }
    ]
}
```
