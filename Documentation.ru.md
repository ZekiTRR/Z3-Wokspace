## 1. Введение

### 1.1 Что такое Z3 Workbench?

Z3 Workbench — графический инструмент в стиле IDE, построенный вокруг
доказателя теорем Z3. Вы описываете **задачу** — набор *переменных* и
*ограничений* на них — нажимаете `Solve` и получаете один из трёх исходов:

| Исход | Значение |
|---|---|
| **SAT** | SAT (от англ. *satisfiable* — «выполнимо»): существует хотя бы одно решение. Workbench показывает конкретное решение — *модель*. |
| **UNSAT** | UNSAT (от англ. *unsatisfiable* — «невыполнимо»): решения не существует, ограничения противоречат друг другу. |
| **UNKNOWN** | UNKNOWN (от англ. *unknown* — «неизвестно»): решатель не смог дать ответ в отведённый бюджет (например, истёк таймаут на очень тяжёлой задаче). |

### 1.2 Основные термины

| Термин | Определение |
|---|---|
| **SMT** | SMT (*Satisfiability Modulo Theories* — «выполнимость по модулю теорий») — задача определения выполнимости логической формулы относительно фоновых теорий: целых чисел, битовых векторов, строк и т. д. |
| **Solver** | Решатель — движок, который определяет выполнимость. В Z3 Workbench используется Z3 от Microsoft. |
| **Задача (problem)** | Именованный набор переменных и ограничений. Хранится внутри проекта. |
| **Переменная** | Именованное значение с типом (`Int`, `Bool`, …). Решатель присваивает переменным значения. |
| **Ограничение (constraint)** | Логическое (булево) выражение над переменными, которое обязано выполняться в любом решении. |
| **Модель (model)** | Конкретная таблица «переменная → значение», удовлетворяющая всем ограничениям. Показывается после SAT. |
| **Сорт (sort)** | Формальное название домена/типа значения (`Int`, `BitVec(32)`, …). |
| **Литерал** | Записанная константа: `42`, `0x1337`, `true`, `"text"`. |
| **DSL** | DSL (*Domain-Specific Language* — предметно-ориентированный язык) — небольшой язык, определённый приложением для ручного описания задач. |

### 1.3 Принципы устройства

- **Текст на DSL — источник истины.** Каждая задача хранит свой
  редактируемый текст; разобранные сущности пересобираются из него. В файлах
  проектов хранится именно текст.
- **В Z3 не попадает ничего непроверенного.** Текст → лексер → парсер →
  семантический анализ (типы, ширины, неизвестные имена) → внутреннее
  дерево выражений → Z3.
- **Интерфейс никогда не блокируется.** Решение выполняется в отдельном
  потоке; `Stop` отменяет кооперативно.

## 2. Быстрый старт

От запуска до первой решённой задачи:

1. **Запустите приложение.** Стартовая задача (`problem_1`) уже создана и
   содержит:
   ```dsl
   var x: Int

   constraint x > 0
   ```
2. **Замените содержимое редактора** на пример-crackme — классическую форму
   «найди x, при котором…» из reverse engineering:
   ```dsl
   var x: BitVec(32)

   constraint ((x ^ 0x1337) + 10) == 0x4242
   ```
3. Пока вы печатаете, следите за областью **DIAGNOSTICS** под редактором:
   там в реальном времени перечисляются синтаксические и типовые ошибки с
   номерами строк. Пустой список — задача разобрана чисто.
4. Нажмите **`F5`** (или кнопку **Solve**, или `Ctrl+Enter`).
5. Прочитайте результат:
   - Статус-бар стал зелёным: `Status: SAT`, рядом время решения.
   - Правая панель заполнилась: `x = 0x0000510f (20751)`.
   - Консоль внизу зафиксировала каждый шаг.

Вы только что решили `(x ^ 0x1337) + 10 == 0x4242`: ответ `x = 0x510F`.
Кликните по значению — оно скопируется в буфер обмена.

## 4. Справочник синтаксиса DSL

В DSL (предметно-ориентированном языке) ровно **два вида инструкций**:

```ebnf
program     = { statement } ;
statement   = var-decl | constraint ;
var-decl    = "var" identifier ":" type ;
constraint  = "constraint" expression ;
type        = "Bool" | "Int" | "Real" | "String" | "BitVec" "(" number ")" ;
expression  = ... инфиксные операторы над литералами и идентификаторами ...
```

Всё остальное — комментарии, пробелы, порядок инструкций — свободно.

### 4.1 Структура программы

- Инструкции **не завершаются** `;` или переводом строки. Новая инструкция
  распознаётся по ключевому слову (`var` / `constraint`), поэтому
  форматирование произвольно.
- Порядок инструкций не важен: ограничения можно писать до переменных,
  которые они используют. Внутри сначала собираются все объявления, затем
  ограничения разрешаются относительно них.
- Ключевые слова чувствительны к регистру: `var` работает, `Var` — нет.
- Имена типов — тоже ключевые слова; переменными они быть не могут.

Корректная программа с необычным форматированием:

```dsl
constraint y > x var x: Int var y: Int
```

Рекомендуемый стиль (используется во всём руководстве):

```dsl
var x: Int
var y: Int

constraint x >= 10
constraint y == x + 20
```

Пустая строка между блоком объявлений и ограничениями — соглашение, а не
синтаксис.

### 4.2 Идентификаторы

Идентификатор (имя переменной):

```ebnf
identifier = ( letter | "_" ) , { letter | digit | "_" } ;
letter     = "A".."Z" | "a".."z" ;   digit = "0".."9" ;
```

- Только ASCII-буквы; Unicode не допускается.
- Не начинается с цифры.
- Нарушения дают: ``Invalid variable name '...'``.
- Имена уникальны внутри задачи: ``Variable "x" is already defined``.
- Зарезервированные слова (`var`, `constraint`, `true`, `false`, `Bool`,
  `Int`, `Real`, `String`, `BitVec`) лексер распознаёт как ключевые —
  переменными они быть не могут.

### 4.3 Переменные — команда `var`

```ebnf
var-decl = "var" identifier ":" type ;
```

Объявляет переменную и фиксирует её сорт. Сортов пять:

#### `Bool`

Двузначная логика: `true` / `false`.

#### `Int`

Математические целые — **произвольной точности, без переполнения**. Никаких
32-битных заворачиваний здесь нет; для машинной арифметики используйте
`BitVec`. Литералы: десятичные, шестнадцатеричные (`0x…`), двоичные
(`0b…`).

> Целочисленные деление `/` и остаток `%` для `Int` **в DSL не входят**
> (см. §4.7): `/` зарезервирован за `Real` и `BitVec`.

#### `Real`

Точные рациональные числа (не бинарная плавающая точка!). Значения хранятся
и вычисляются как рациональные дроби, поэтому `1 / 3 * 3 == 1` выполняется
точно. Литералы — десятичные с обязательными цифрами после точки: `3.14`,
`0.5`. В моделях вещественные показываются десятичными строками.

#### `String`

Строки UTF-8. Доступны только сравнения на равенство (§4.7); строковых
функций (длина, конкатенация) пока нет.

#### `BitVec(N)`

Битовый вектор фиксированной ширины — семантика машинного слова. `N` —
ширина в битах, от 1 до 64 (``BitVec width must be between 1 and 64``).
Типичные варианты:

```dsl
var flags: BitVec(8)
var port : BitVec(16)
var eax  : BitVec(32)
var ptr  : BitVec(64)
```

Семантика:

- Арифметика — **по модулю 2^N** (заворачивается, как беззнаковые типы C):
  на `BitVec(32)` верно `0xFFFFFFFF + 1 == 0`.
- Сравнения `< <= > >=` — **беззнаковые** (как принято в RE-инструментах).
  Знаковых вариантов в DSL нет.
- Деление `/` и остаток `%` — **беззнаковые** (`bvudiv`/`bvurem`).
- Сдвиги `<< >>` — **логические** (`bvlshr` для `>>`; арифметического/
  знакового сдвига нет).
- Унарный минус `-` к BitVec в DSL **неприменим** (§4.7).

### 4.4 Ограничения — команда `constraint`

```ebnf
constraint = "constraint" expression ;
```

Добавляет утверждение: булево выражение, которое обязано выполняться в
любом решении. Корень выражения должен быть булевым:

```dsl
constraint x >= 10          // ОК: сравнение даёт Bool
constraint x + 1            // ОШИБКА: Constraint must be a Boolean expression, got Int
```

Ограничения можно временно отключать — пока только удаляя или комментируя
их (`//`).

Несколько ограничений неявно объединяются логическим И.

### 4.5 Литералы

| Вид | Формы | Примеры |
|---|---|---|
| Целый | десятичный | `0`, `42`, `-7`* |
| Целый | шестнадцатеричный `0x`/`0X` | `0x1337`, `0Xff` |
| Целый | двоичный `0b`/`0B` | `0b1010`, `0B11` |
| Вещественный | десятичный с дробной частью | `3.14`, `0.5`, `-2.75`* |
| Логический | ключевые слова | `true`, `false` |
| Строковый | двойные кавычки | `"hello"`, `"a\"b"` |

\* отрицательные значения получаются унарным минусом, применённым к
положительному литералу (§4.7); сам литерал неотрицателен.

Правила и ловушки:

- Для hex/bin нужна хотя бы одна цифра: голое `0x` →
  ``Hexadecimal literal has no digits``.
- Вещественные требуют цифр после точки: `1.` →
  ``Malformed real literal (missing digits after '.')``.
- Число, склеенное с буквами, отклоняется без каскада:
  `123abc` → ``Malformed number literal``.
- Целые за пределами 64-битного знакового диапазона →
  ``Integer literal '...' is out of range``. (Для огромных констант
  используйте контексты `BitVec` либо разбивайте константу.)
- Строковые escape: `\\`, `\"`, `\n`, `\t`. Любой другой →
  ``Unknown escape sequence '\X'``. Незакрытая строка (перевод строки или
  конец файла до закрывающей кавычки) — ошибка.
- В выражениях обычный целый литерал автоматически подстраивается под
  окружающий контекст BitVec (§4.9).

### 4.6 Комментарии

```dsl
// строчный комментарий — до конца строки

/* блочный комментарий;
   может занимать несколько строк */
var x: Int /* встроенный */ // хвостовой комментарий
```

Блочные комментарии **не вкладываются**. Незакрытый `/*` без `*/` — ошибка.

Комментарии допустимы везде, где допустимы пробелы.

### 4.7 Справочник операторов

Унарные операторы:

| Оператор | Сорта операнда | Результат | Семантика |
|---|---|---|---|
| `!` | `Bool` | `Bool` | Логическое отрицание (`not`) |
| `-` | `Int`, `Real` | тот же | Арифметическое отрицание. **К `BitVec` неприменимо** — отрицание битовых векторов в DSL пока не выражается. |
| `~` | `BitVec(N)` | `BitVec(N)` | Побитовое НЕ (`bvnot`), инвертирует все N бит |

Бинарные операторы, по семействам:

| Оператор | Сорта операндов | Результат | Семантика / бэкенд |
|---|---|---|---|
| `\|\|` | `Bool` × `Bool` | `Bool` | Логическое ИЛИ |
| `&&` | `Bool` × `Bool` | `Bool` | Логическое И |
| `==` | одинаковый сорт¹ | `Bool` | Равенство (`=`) |
| `!=` | одинаковый сорт¹ | `Bool` | Неравенство (`distinct`) |
| `<` `<=` `>` `>=` | `Int`×`Int`, `Real`×`Real`, `BitVec(W)`×`BitVec(W)` | `Bool` | Порядок. Для BitVec — **беззнаково** (`bvult`, `bvule`, `bvugt`, `bvuge`). Ширины обязаны совпадать. |
| `+` `-` `*` | `Int`, `Real`, `BitVec(W)` (одинаковый сорт с обеих сторон) | тот же | Арифметика. На BitVec — по модулю 2^W. |
| `/` | `Real`×`Real`, `BitVec(W)`×`BitVec(W)` | тот же | Точное рациональное деление; **беззнаковое** деление (`bvudiv`). Целочисленное `/` отбрасывается проверкой типов. |
| `%` | `BitVec(W)`×`BitVec(W)` | `BitVec(W)` | Беззнаковый остаток (`bvurem`). Целочисленный `%` отбрасывается проверкой типов. |
| `&` \| `^` | `BitVec(W)`×`BitVec(W)` | `BitVec(W)` | Побитовые И/ИЛИ/ИСКЛЮЧАЮЩЕЕ ИЛИ (`bvand`, `bvor`, `bvxor`) |
| `<<` `>>` | `BitVec(W)`×`BitVec(W)` | `BitVec(W)` | Сдвиг влево / **логический** сдвиг вправ (`bvshl`, `bvlshr`) |

¹ Разрешённые сорта для равенства: `Bool`, `Int`, `Real`, `String`,
`BitVec(W)` (одинаковая ширина с обеих сторон). Сорта операндов обязаны
совпадать; ничего не приводится, кроме правила литералов из §4.9.

Все бинарные операторы — **левоассоциативные**.

Примечания:

- «Короткое замыкание» `&&`/`||` здесь нерелевантно: вся формула целиком
  уходит решателю.
- Побитовых операторов для `Int` нет — переведите переменную в `BitVec`.
- Оператора возведения в степень нет.

### 4.8 Приоритеты и ассоциативность

От самого слабого связывания к самому сильному:

| Уровень | Операторы | Примечание |
|---|---|---|
| 1 | `\|\|` | самый слабый |
| 2 | `&&` | |
| 3 | `==` `!=` | |
| 4 | `<` `<=` `>` `>=` | |
| 5 | `&` `\|` `^` | побитовые связывают сильнее сравнений — в отличие от C! |
| 6 | `<<` `>>` | |
| 7 | `+` `-` | |
| 8 | `*` `/` `%` | |
| 9 | унарные `!` `-` `~` | самый сильный |

Скобки всегда перекрывают приоритеты.

Разбор неоднозначностей (канонические полностью-скобочные формы):

| Исходник | Разбирается как |
|---|---|
| `x ^ 0x1337 == 0x4242` | `(x ^ 0x1337) == 0x4242` |
| `1 + 2 * 3 == 7` | `(1 + (2 * 3)) == 7` |
| `true \|\| false && true` | `true \|\| (false && true)` |
| `x & 1 << 2` | `x & (1 << 2)` |
| `-x + y < 0` | `((-x) + y) < 0` |

Первая строка — осознанное решение: побитовые операции связывают сильнее
сравнений, поэтому RE-уравнения читаются естественно. В C то же выражение
разобралось бы как `x ^ (0x1337 == 0x4242)`.

### 4.9 Автоматическая адаптация целых литералов к BitVec

Внутри любой операции, у которой другой операнд — `BitVec`, обычный целый
литерал автоматически расширяется до ширины этого операнда:

```dsl
var x: BitVec(32)

constraint (x ^ 0x1337) + 10 == 0x4242   // 0x1337, 10, 0x4242 становятся BitVec(32)
constraint x < 100                        // 100 становится BitVec(32)
constraint (x << 2) > 0                   // 2 становится BitVec(32)
```

Правила:

- Адаптация применяется к **обычному целому литералу, стоящему операндом
  напрямую** — не к вычисленным подвыражениям.
- Проверка диапазона относительно ширины: литерал должен удовлетворять
  `0 ≤ v < 2^W`.
  - Отрицательный литерал → ``Negative integer literal cannot be used as BitVec(W)``
  - Слишком большой → ``Integer literal N does not fit into BitVec(W)``
- Без контекста BitVec литерал остаётся `Int`.

### 4.10 Сводка правил типизации

1. Операнды каждого бинарного оператора обязаны иметь одинаковые сорта
   (единственное исключение — адаптация литералов из §4.9).
2. `Int` и `Real` никогда не смешиваются: `r == i + 1.5` при `i: Int`,
   `r: Real` → ``Type mismatch: operator '+' requires numeric operands of the same sort, got Int and Real``.
   Смените объявленный сорт переменной явно.
3. Операнды BitVec обязаны совпадать по ширине точно: `a & b` при
   `a: BitVec(8)`, `b: BitVec(16)` → несоответствие с указанием `BitVec(8)`.
4. Для строк доступны только `==` / `!=`; сравнения порядка на строках
   отклоняются.
5. Корень каждого `constraint` обязан быть `Bool`.

## 5. Создание и решение задачи

Типовой сценарий:

1. **Создайте задачу** — `Ctrl+N` или Explorer ▸ `New`. Задачи получают
   автогенерированные имена (`problem_1`, `problem_2`, …), так что можно
   сразу печатать. Вставляется стартовый шаблон.
2. **Переименуйте** (по желанию) — выберите в Explorer, `Rename`, введите
   корректный идентификатор.
3. **Напишите переменные и ограничения** — см. §4. Исправляйте диагностики,
   пока список под редактором не опустеет.
4. **Решайте** — `F5`, кнопка `Solve` или `Ctrl+Enter` прямо из редактора.
   - Задача уходит в рабочий поток; интерфейс остаётся отзывчивым.
   - Во время работы статус-бар показывает `Solving…`, `Solve` заблокирована,
     `Stop` активна.
5. **Изучите модель** (SAT) — правая панель; клик по значению копирует его.
6. **Итерируйте** — добавляйте/убирайте ограничения и перерешивайте. Чтобы
   вручную перечислять несколько решений, исключайте найденные, например
   после `x = 11`:
   ```dsl
   constraint x != 11
   ```
7. **Сохраняйте** — `Ctrl+S` сохраняет проект (`.z3w`). Первое сохранение
   спросит путь; дальше используется тот же (`Ctrl+Shift+S` — «сохранить
   как»). Несохранённые изменения помечены `*` в заголовке окна и на кнопке
   Save.
8. **Экспортируйте/делитесь** — File ▸ Export Problem ▸ SMT-LIB2 / JSON /
   TXT (§9).

Сводка управления задачами (кнопки Explorer):

| Действие | Поведение |
|---|---|
| New | Добавляет `problem_N`, выбирает её, вставляет стартовый шаблон |
| Duplicate | Полная копия с новыми внутренними id и переписанными ссылками на переменные; к имени добавляется `_copy` |
| Rename | Проверяет корректность идентификатора и уникальность |
| Delete | Удаляет задачу; при необходимости сбрасывает выбор |

## 6. Примеры

Все примеры ниже разбираются и решаются в текущей сборке.

### 6.1 Простые границы

```dsl
var x: Int

constraint x >= 10
constraint x <= 100
```

Результат: `SAT`, некоторое `x` из `[10, 100]` (например, `10`).

### 6.2 Система уравнений

```dsl
var x: Int
var y: Int
var z: Int

constraint x + y + z == 30
constraint x - y == 2
constraint z == 2 * x
```

Результат: `SAT`, например `x = 8, y = 6, z = 16`.

### 6.3 Противоречие (UNSAT)

```dsl
var x: Int

constraint x > 10
constraint x < 5
```

Результат: `UNSAT`. Полезно для проверки конвейера: модель не появляется,
консоль сообщает, что решения не существует.

### 6.4 Логическая головоломка

```dsl
var p: Bool
var q: Bool
var r: Bool

constraint p || q || r
constraint !(p && q)
constraint q == r
```

Результат: `SAT`; посмотрите, какие наборы удовлетворяют всем трём clauses.

### 6.5 Классический crackme (BitVec)

Найдите `x`, для которого XOR с `0x1337` и прибавление 10 дают `0x4242`:

```dsl
var x: BitVec(32)

constraint ((x ^ 0x1337) + 10) == 0x4242
```

Ручной вывод: `x = (0x4242 − 10) ^ 0x1337 = 0x4238 ^ 0x1337 = 0x510F`.
Модель показывает `x = 0x0000510f (20751)` — совпадает.

Обратите внимание, как целые литералы `10` адаптировались к `BitVec(32)`
(§4.9).

### 6.6 Извлечение байтов и маски (стиль RE)

```dsl
var v: BitVec(32)

constraint (v & 0xFF) == 0x41                 // младший байт — 'A'
constraint ((v >> 8) & 0xFF) == 0x42          // следующий байт — 'B'
constraint ((v >> 16) & 0xFF) == 0            // третий байт нулевой
constraint (v >> 24) == 0                     // старший байт нулевой
```

Результат: `SAT`, `v = 0x00004241 (16961)` — четыре ограничения
фиксируют каждый байт, поэтому ответ единственный.

### 6.7 Заворачивающая арифметика

```dsl
var a: BitVec(8)

constraint a == 255
constraint a + 1 == 0
```

Результат: `SAT` — демонстрация заворачивания по модулю 256. На `Int`
вторая строка сделала бы задачу UNSAT.

### 6.8 Строки

```dsl
var password: String

constraint password != ""
constraint password == "s3cr3t"
```

Результат: `SAT`, `password = s3cr3t`. Доступны только `==`/`!=`;
механизмов длины/подстрок пока нет (§12).

### 6.9 Рациональная арифметика

```dsl
var total: Real
var part : Real

constraint total == 10
constraint part == total / 4
constraint part * 4 == total
```

Результат: `SAT`, `part = 2.5`. Вещественные — точные рациональные:
`0.1 + 0.2 == 0.3` дало бы SAT (в отличие от бинарной плавающей точки).

### 6.10 Тяжёлая задача → UNKNOWN по таймауту

```dsl
var f1: Int
var f2: Int

constraint f1 > 1
constraint f2 > 1
constraint f1 * f2 == 999999670000016821
```

Факторизация большого полупростого числа выходит за бюджет по умолчанию
(5000 мс). Ожидаемый результат: `UNKNOWN` с диагностикой в консоли вида
`Reason: timeout` (точный текст причины приходит от Z3). Это честный ответ —
решатель не доказал невыполнимость и не нашёл модель.

## 7. Чтение результатов

### 7.1 Статусы

| Статус | Цвет | Значение | Панель модели |
|---|---|---|---|
| `SAT` | зелёный | Решение найдено | Значения заполнены |
| `UNSAT` | жёлтый | Решения не существует | Очищена |
| `UNKNOWN` | синий | Не решено (например, таймаут) | Очищена; в логе `Reason:` |
| `ERROR` | красный | Сбой бэкенда (например, неподдерживаемая конструкция) | Очищена |
| `INVALID` | красный | В тексте редактора сейчас есть диагностики | Прежние значения очищены |
| `Solving…` / `Cancelling…` | акцентно-синий | Задача выполняется | — |

### 7.2 Значения модели

- Каждая объявленная переменная получает значение; даже неограниченные
  переменные получают произвольное удовлетворяющее присваивание.
- Форматы: `Int` — десятичный; `Bool` — `true/false`; `Real` — десятичная
  строка; `String` — текст как есть; `BitVec(W)` — `0x` + hex, дополненный
  до W/4 цифр + десятичное в скобках, например `0x0000510f (20751)`.
- **Клик по значению копирует его** в буфер обмена.
- За один запуск возвращается только ОДНА модель. Для поиска альтернатив
  исключайте известные значения (§5, шаг 6).

### 7.3 Консоль

Каждый запуск добавляет строки вида:

```text
[20:41:02] INFO    Parsing problem... done
[20:41:02] INFO    Variables: 1, Constraints: 1 (of 1 enabled)
[20:41:02] INFO    Starting Z3...
[20:41:02] INFO    Result: SAT
[20:41:02] INFO    Solver time: 8 ms
```

Предупреждения и ошибки идут со своими уровнями; при UNKNOWN добавляется
строка `Reason:` (например, timeout). Если до завершения задачи вы
переключили задачу, результат отбрасывается с пометкой, а не портит вид.

### 7.4 Время

В статус-баре показываются миллисекунды реального времени всего запроса
решения (от разбора до модели). Малые задачи обычно дают единицы
миллисекунд.

## 8. Каталог диагностик

Сообщения появляются в списке DIAGNOSTICS с префиксом `Line N:`, где
позиции известны. Точные тексты:

### Лексер

| Сообщение | Причина / исправление |
|---|---|
| `Unexpected character '=' (did you mean '=='?)` | Введён одиночный `=`; равенство — `==`. |
| `Unexpected character 'X'` | Символ вне алфавита DSL (например, `@`, `;`). |
| ``Hexadecimal literal has no digits`` | Голое `0x`. |
| `Binary literal has no digits` | Голое `0b`. |
| `Malformed hexadecimal literal` | Мусор, приклеенный к hex-числу (`0xFFG`). |
| `Malformed binary literal` | Например, `0b102`. |
| `Malformed number literal` | Цифры, за которыми идут буквы (`123abc`). Числовой префикс сохраняется для восстановления. |
| ``Malformed real literal (missing digits after '.')`` | Стиль `1.`. |
| `Unknown escape sequence '\X'` | В строках существуют только `\\ \" \n \t`. |
| `Unterminated string literal` | Нет закрывающей кавычки (строки не переносятся на новую строку). |
| `Unterminated block comment` | `/*` без `*/`. |

### Парсер

| Сообщение | Причина / исправление |
|---|---|
| ``Expected 'var' or 'constraint', found …`` | Инструкция вне двух допустимых форм. Восстановление перескакивает к следующему ключевому слову. |
| `Expected variable name` / ``Invalid variable name '...'`` | Правила §4.2. |
| ``Expected ':' after variable name`` | `var x Int` → вставьте `:`. |
| ``Expected '(' after 'BitVec'`` / `Expected bit width` / ``Expected ')' after bit width`` | Некорректный `BitVec(...)`. |
| ``BitVec width must be between 1 and 64`` | Диапазон ширин. |
| ``Expected a type (Bool, Int, Real, String, BitVec), found …`` | Неизвестное имя типа. |
| ``Expected ')', found …`` / `Unexpected token …` | Ошибки скобок/операторов. Несколько ошибок сообщаются за один проход благодаря восстановлению по инструкциям. |
| ``Integer literal '...' is out of range`` | За пределами 64-битного знакового. |

### Семантический анализ

| Сообщение | Причина / исправление |
|---|---|
| ``Variable "x" is already defined`` | Дублирующий `var`. |
| ``Unknown variable "foo"`` | Использование до объявления или опечатка — помните: порядок не важен, значит имени действительно нет. |
| ``Type mismatch: operator 'OP' requires …, got A and B`` | Нарушение семейства: например, `&&` над Int, `&` над Int, `+` со смешением сортов. |
| ``Type mismatch: cannot compare A with B`` | `==`/`!=`/порядок между разными сортами или ширинами. |
| ``Operator 'OP' cannot be applied to TYPE`` | Ошибка унарного: `-x` на BitVec, `~flag` на Bool, `!x` на Int. |
| ``Constraint must be a Boolean expression, got TYPE`` | Корень `constraint` не Bool. |
| ``Negative integer literal cannot be used as BitVec(W)`` | §4.9. |
| ``Integer literal N does not fit into BitVec(W)`` | §4.9, v ≥ 2^W. |
| `Function calls are not supported yet: "..."` | Синтаксис вызовов зарезервирован. |

### Решатель / импорт

| Сообщение | Причина / исправление |
|---|---|
| `Reason: …` после UNKNOWN | Собственная причина Z3 (обычно `timeout`). |
| `Solving was cancelled before it started` | Нажат Stop до отправки задачи. |
| ``Sort 'Array' is not supported yet (variable "…")`` | Сорт Array зарезервирован. |
| `Import failed: Line N: …` | Ошибки чтения SMT-LIB2 (§9.4). |
| `Open failed: …` / `Save failed: …` | Проблемы ввода-вывода файла проекта (нет файла, недоступный путь, невалидный JSON, неверная версия схемы). |

## 9. Файлы: проекты, экспорт, импорт

### 9.1 Файлы проектов (`.z3w`)

Проект объединяет все задачи. Формат: JSON, версия схемы 1:

```json
{
    "version": 1,
    "name": "Example",
    "problems": [
        {
            "name": "crackme_01",
            "source": "var x: BitVec(32)\n\nconstraint ((x ^ 0x1337) + 10) == 0x4242\n"
        }
    ]
}
```

Стоит знать о дизайне:

- Хранятся только **имена + DSL-тексты**. Переменные и ограничения
  пересобираются настоящим парсером при загрузке, поэтому файл проекта
  физически не может «разойтись» с реализацией языка.
- Загрузка валидирует каждый текст; задача, чей текст больше не
  парсится, даёт ошибку `Format` с именем задачи.
- Файлы, записанные более новой версией схемы, отклоняются с понятным
  сообщением (в загрузчик встроена цепочка миграций).
- Операции блокируются, пока идёт решение.

### 9.2 Экспорт

File ▸ Export Problem ▸ … экспортирует **выбранную сейчас задачу**
(отражая самый свежий текст редактора, если он разбирается).

**SMT-LIB2** (`.smt2`) — переносимый документ, независимый от внутренностей
Z3; годится для любого SMT-LIB2-решателя:

```lisp
(declare-const x (_ BitVec 32))
(assert (= (+ (bvxor x (_ bv4919 32)) (_ bv10 32)) (_ bv16962 32)))
(check-sat)
(get-model)
```

Примечания: операции BitVec отображаются в беззнаковые функции (`bvudiv`,
`bvurem`, `bvult`…); отрицание выбирает `bvneg` против `-` по выведенному
сорту.

**JSON** (`.json`) — структурный дамп: имя, исходник, переменные (с
ширинами), ограничения в канонической форме отображения, флаг enabled,
комментарий, строка исходника.

**TXT** (`.txt`) — человекочитаемый листинг:

```text
Problem: crackme_01

Variables:
  x : BitVec(32)

Constraints:
  [x] ((x ^ 0x1337:32) == 0x4242:32)    (line 3)
```

### 9.3 Два вида SMT-LIB2

| Вид | Как открыть | Содержимое |
|---|---|---|
| **Вид бэкенда** | просмотрщик `Ctrl+M` | Рендерит сам Z3 по тому, что адаптер реально передаёт — лучше всего для отладки конвертера. |
| **Переносимый экспорт** | File ▸ Export ▸ SMT-LIB2 | Создаётся собственным сериализатором workbench из доменного дерева — независим от бэкенда, стабильное форматирование. |

### 9.4 Импорт SMT-LIB2

File ▸ Import SMT-LIB2 читает подмножество, порождаемое экспортёром:
команды `declare-const` / `assert` над сортами и операторами workbench.

- Неизвестные команды (`check-sat`, `set-info`, `set-logic`, …)
  пропускаются.
- Неподдерживаемые конструкции (квантификаторы, неинтерпретируемые
  функции, массивы) дают `Import failed: Line N: Unsupported operator "…"`.
- Импортированная задача становится **полноценной задачей DSL**: reader
  восстанавливает выражения, DSL-принтер генерирует редактируемый
  исходник, дальше работает обычный конвейер
  валидации/решения/сохранения. Имя задачи берётся из имени файла
  (уникализируется суффиксом).

### 9.5 Недавние проекты

Последние 10 открытых/сохранённых путей проектов переживают перезапуск
(File ▸ Open Recent). Записи открываются одним кликом.

## 12. Известные ограничения

Текущие осознанные границы MVP (это точки расширения, а не дефекты):

1. **Нет отрицания и знаковых сравнений для BitVec в DSL**: унарный `-`
   применим только к Int/Real. Вычитание эмулируйте через `+` с
   адаптированными литералами.
2. **Нет знаковой семантики BitVec**: сравнения, `/`, `%`, `>>` —
   беззнаковые. Знаковые варианты — будущие операторы.
3. **Целочисленные `/` и `%` не входят в DSL**: `/` — только для Real,
   `%` — только для BitVec. Задачи о делимости целых формулируйте через
   умножение.
4. **Сорт Array зарезервирован, но не поддерживается**; то же для float и
   enum.
5. **Строки: только равенство** — длины/конкатенации/регулярок пока нет.
6. **Одна модель за запуск**; альтернативы перечисляйте, исключая
   предыдущие значения вручную.
7. **Вызовы функций** в выражениях недоступны (синтаксис зарезервирован).
8. **Нет интерфейса опций решателя** (таймаут фиксирован на 5000 мс в этой
   сборке); статистика собирается в результат, но отдельной панели пока нет.
9. **Unsat cores / оптимизация / push-pop** готовы архитектурно, но ещё не
   выставлены наружу.
